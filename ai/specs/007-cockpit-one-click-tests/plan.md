# 实现计划

## 方案

在 `ai/quality/qualitylib/` 新增核心测试运行器和专用 HTTP handler。运行器通过依赖注入的进程
执行边界启动 Django 与 Jest，解析测试数量并返回统一结果。handler 在现有静态服务上增加以下接口：

- `POST /api/core-tests/run`：启动测试并等待完成。
- 要求客户端地址为回环地址，并要求 `X-Cockpit-Test-Run: 1` 请求头，避免普通浏览器表单跨站触发。
- 运行器使用进程锁拒绝并发测试；子进程设置超时和输出上限。

驾驶舱页面增加回归测试面板和内联 JavaScript。脚本只通过 `textContent` 渲染服务端文本，不拼接
HTML；使用 `fetch` 调用同源接口，并更新按钮禁用状态、进行中提示、结果卡片和失败输出。

## 影响面

- 后端：新增本地驾驶舱测试 API 和进程运行器，不改变业务 API。
- 前端：驾驶舱内联脚本和样式，不改变管理端 Vue 页面。
- 数据与迁移：无；测试使用独立内存数据库。
- 部署与配置：仅 `quality.py serve` 开发工具新增接口，生产应用不注册该入口。

## 验证策略

- 先写运行器测试，用注入的进程执行替身验证成功、失败、超时与并发拒绝。
- 再写真实 HTTP 服务测试，验证同源 API、专用请求头、本机限制和响应结构。
- 更新驾驶舱生成测试，验证按钮、内联脚本、无外部资源和 file 模式提示。
- 刷新驾驶舱并实际点击，检查后端 91 项、前端 56 项结果。
- 运行 quick、核心测试和 full，记录真实结果。

## 回滚方案

停止 `quality.py serve` 并回退 handler、运行器及驾驶舱模板即可恢复纯静态页面。业务数据、数据库
结构和生产部署不受影响。
