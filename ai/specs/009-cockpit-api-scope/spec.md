# 驾驶舱一键测试 API 范围展示

## 背景与问题

驾驶舱的一键测试只显示后端/前端套件结果，使用者无法确认本次到底覆盖了哪些 API。点击运行后，
需要能够看到按模块分组的 HTTP 方法和路径，同时避免页面文案与实际测试范围逐渐不一致。

## 目标

- 一键测试面板展示 API 覆盖清单，按用户、角色、菜单、部门分组。
- 点击“一键测试核心功能”时自动展开 API 清单。
- API 元数据由测试运行器和驾驶舱共用，避免两边维护不同列表。
- 清单只展示实际回归覆盖的接口，不把仅有序列化测试的接口描述成完整 API 测试。

## 非目标

- 不逐接口生成实时进度，也不改变现有后端和前端测试范围。
- 不增加外部请求、API 文档服务或新的前端依赖。

## 用户故事

- 作为维护者，我希望执行一键测试时知道具体会调用哪些接口，从而判断回归范围是否足够。
- 作为开发者，我希望 API 清单与测试元数据来自同一来源，从而避免文档漂移。

## 验收标准

- [x] AC-001 一键测试区域显示可展开的 API 清单，点击测试时自动展开。
  验证：`test_cockpit.py` 与浏览器交互检查。
- [x] AC-002 清单按用户、角色、菜单、部门分组，包含 HTTP 方法和路径。
  验证：`test_cockpit.py` 检查 38 个实际覆盖的 method/path 组合。
- [x] AC-003 测试运行器响应包含同一份 API 范围元数据。
  验证：`test_test_runner.py`。

## 约束与风险

- API 清单是测试覆盖说明，不表示外部客户端只能调用这些接口。
- 页面仍需保持无外部资源依赖，并安全渲染动态文本。
