# 工程驾驶舱视觉与可读性优化

## 背景与问题

现有驾驶舱已经能展示规格、验证门禁和代码资产，但页面结构接近通用表格，状态信息缺少
视觉权重，长表格在窄屏上也不易浏览。维护者需要在打开页面后快速判断质量状态，并继续查看
规格进度和失败详情。

## 目标

- 建立清晰的“总览、规格、验证、资产与命令”信息层级。
- 用统一的颜色、间距和组件语言强化通过、失败、部分验证与未验证状态。
- 在桌面和手机上保持内容可读、触控友好且没有页面级横向溢出。
- 保持驾驶舱为无外部依赖的静态 HTML，并完整保留现有数据与安全转义行为。

## 非目标

- 不改变质量门禁规则、报告 JSON schema 或规格解析逻辑。
- 不增加实时刷新、远程数据请求、账号体系或生产数据接入。
- 不引入前端框架、外部字体、图标 CDN 或构建步骤。

## 用户故事

- 作为项目维护者，我希望一眼看到质量结论和关键指标，从而判断当前是否适合合入或发布。
- 作为开发者，我希望规格进度与失败门禁更容易扫读，从而快速定位下一步。
- 作为手机用户，我希望表格和详情改为纵向卡片，从而无需反复横向拖动。

## 验收标准

- [x] AC-001 桌面端页面形成明确的标题区、状态总览、规格区、验证区与辅助信息区分层，核心状态在第一屏可见。
  验证：`python -m unittest ai.quality.tests.test_cockpit` 与 1440px 宽浏览器截图人工检查。
- [x] AC-002 390px 窄屏下导航、指标卡、规格和门禁内容纵向重排，页面无横向溢出且操作入口仍可点击。
  验证：自动化断言响应式 CSS 规则，并使用 390px 宽浏览器截图人工检查。
- [x] AC-003 现有规格、质量报告、覆盖率、代码资产、命令、失败详情和安全转义均继续渲染。
  验证：`python -m unittest ai.quality.tests.test_cockpit` 的回归用例。
- [x] AC-004 页面保持单文件静态输出，不请求外部脚本、样式、字体或图片。
  验证：`test_cockpit.py` 断言生成 HTML 无外部资源 URL，且驾驶舱可本地打开。

## 约束与风险

- 输出仍是 `ai/cockpit/index.html`，同时支持直接打开和通过 `quality.py serve` 浏览。
- 仅使用系统字体和 CSS 绘制视觉元素，避免离线环境出现资源缺失。
- 状态颜色不能作为唯一信息载体，徽标必须同时显示文字。
- 大幅调整布局时保留现有测试依赖的标题、状态和命令文本。
- 前端 lint 已清零，`full` 10/10 通过；后续视觉改动仍需保持无外部依赖和响应式检查。
