# 实现计划

## 方案

在 `ai/quality/qualitylib/cockpit.py` 内重构静态模板与 CSS，继续复用规格解析、质量报告、
覆盖率扫描和资产统计结果。页面改为顶部工作台导航与总览，再按规格、门禁、资产/命令分区；
规格与门禁表格在窄屏下使用基于 `data-label` 的卡片式呈现。

视觉组件集中为状态徽标、指标卡、面板、进度条和命令块。颜色同时搭配可读文字，不用颜色
单独表达状态。全部样式内联，不增加网络请求或运行时脚本。

## 影响面

- 后端：无业务逻辑变化；调整驾驶舱 HTML 生成函数及其辅助渲染函数。
- 前端：仅影响生成的静态驾驶舱页面，不影响 `business/frontend`。
- 数据与迁移：无。
- 部署与配置：无；继续通过 `quality.py cockpit` 和 `quality.py serve` 使用。

## 验证策略

- 扩充 `ai/quality/tests/test_cockpit.py`，覆盖结构标记、响应式规则、状态文案和静态资源约束。
- 重新生成驾驶舱，检查 HTML 内容与现有报告数据一致。
- 使用 1440px 和 390px 宽浏览器截图检查层级、换行、触控尺寸和横向溢出。
- 运行 quick 与 full 质量门禁；若环境依赖导致 full 失败，保留原始证据并明确残余风险。

## 回滚方案

本次只修改驾驶舱生成模板和对应测试。若视觉调整引发兼容问题，可回退 `cockpit.py` 与测试到
上一版本并重新运行 `python ai/quality/quality.py cockpit`；数据报告和质量门禁逻辑不受影响。
