# 登录首页集成工程驾驶舱

## 背景与问题

工程驾驶舱目前作为独立静态 HTML 运行，开发者登录业务前端后仍会进入展示随机演示数据的旧首页。
用户需要在登录后直接看到当前仓库的规格、质量门禁和代码资产状态，同时不能把驾驶舱内容作为
无需登录的公开静态资源暴露，也不能破坏现有独立驾驶舱和本地一键测试入口。

## 目标

- 登录后默认首页直接展示当前工程驾驶舱。
- 驾驶舱内容通过已有 JWT 登录态和 `system:dashboard:view` 权限读取。
- 驾驶舱继续由质量工具统一生成，独立静态页面和前端快照来自同一份数据。
- 左侧菜单将默认入口显示为“驾驶舱”，已有角色关系保持不变。

## 非目标

- 不在生产前端开放“一键测试核心功能”；该能力仍只属于本机 `quality.py serve`。
- 不引入新的图表库、iframe 外站资源或独立驾驶舱服务。
- 不改变质量门禁的判定规则和现有 API 权限模型。

## 用户故事

- 作为已登录的项目维护者，我希望登录后立即看到工程驾驶舱，从而不用再手动打开本地静态文件。
- 作为系统管理员，我希望未登录用户和没有首页权限的用户不能读取驾驶舱快照。

## 验收标准

- [x] AC-001 登录后的默认首页展示工程驾驶舱，不再展示随机用户数、订单数和金额。
  验证：`getFirstAccessiblePath`/菜单回归测试、`CockpitDashboard.spec.js` 与生产构建检查。
- [x] AC-002 驾驶舱快照通过受 JWT 和 `system:dashboard:view` 保护的 API 返回；未认证用户收到 401，
  无权限用户收到 403。
  验证：`business/UniDjango/cockpit/tests.py` 的 API 测试。
- [x] AC-003 `python ai/quality/quality.py cockpit` 同时刷新 `ai/cockpit/index.html` 和后端使用的嵌入式快照，
  且嵌入式快照不包含可执行脚本。
  验证：`ai/quality/tests/test_cockpit.py`。
- [x] AC-004 现有独立驾驶舱仍可生成、服务并通过一键测试相关测试，默认菜单迁移为“驾驶舱”。
  验证：驾驶舱质量测试、菜单迁移测试和 `python ai/quality/quality.py quick`。

## 约束与风险

- JWT 存放于浏览器 sessionStorage，不能用于普通 iframe 导航；前端通过已鉴权的 JSON API 获取快照，
  再用受限 `srcdoc` 展示，避免增加公开静态路由。
- 嵌入式快照必须是只读内容，不能执行脚本或发起跨域请求。
- 已部署数据库需要通过新增迁移更新菜单名称，不能修改历史迁移。
