# 实现计划

## 方案

质量驾驶舱生成器在现有独立 HTML 之外，再生成一个只读嵌入式快照。后端新增受
`system:dashboard:view` 权限保护的 `GET /cockpit/snapshot` API，由前端请求模块携带现有 JWT
读取快照，并把返回的 HTML 放入禁用脚本的 `srcdoc` iframe 中展示。

默认 `/dashboard` 菜单继续作为登录后的首项，只更新菜单位置的名称，避免破坏既有角色菜单和
后端菜单权限。驾驶舱生成逻辑继续复用规格解析、最近质量报告、覆盖率和代码资产统计，保证独立页
与登录首页展示相同数据。

## 影响面

- 后端：新增 `cockpit` Django 应用、快照 API 和权限测试；不新增数据库表。
- 前端：新增驾驶舱 API，改造 `/dashboard` 页面为驾驶舱容器；移除旧随机演示指标。
- 数据与迁移：新增菜单名称迁移，保留原路径、组件和权限标识。
- 部署与配置：后端镜像携带生成后的嵌入式快照；不新增公开静态路由或 Nginx 例外。

## 验证策略

- 先为快照生成、权限边界和首页展示补失败测试。
- 使用 `business/UniDjango/cockpit/tests.py` 覆盖未认证、无权限、有权限和快照缺失分支。
- 使用 `CockpitDashboard.spec.js` 覆盖加载、成功、失败和 `srcdoc` 沙箱属性。
- 运行菜单迁移测试、驾驶舱质量测试、`python ai/quality/quality.py quick`，交付前运行 `full`。

## 回滚方案

回退驾驶舱 API、前端首页及相关测试，并重新部署上一版本前后端镜像即可恢复旧首页。新增菜单名称
迁移只修改展示名称，反向迁移可恢复“首页”，不影响角色授权数据。
