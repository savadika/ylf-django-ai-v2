# 实现计划

## 方案

后端为当前用户增加专用个人资料接口，复用密码强度校验和统一响应信封。用户模型增加
`token_version`，签发 JWT 时写入版本，认证中间件比对数据库版本；密码变更通过模型
方法递增版本，从而撤销该用户全部旧令牌。

生产前端把令牌保存到 `sessionStorage`，Nginx 统一注入安全头。前端补充个人中心交互、
令牌存储、状态管理和动态路由转换测试，并把覆盖率收集范围扩展到核心页面与布局。

部署脚本在读取已有凭证时执行 fail-closed 参数校验，只允许首次部署或
`--reset-admin` 修改管理员。新增公开健康接口，同时验证数据库 `SELECT 1` 和缓存读写；
部署脚本使用宿主机回环地址访问该接口确认后端真正可用。

## 影响面

- 后端：`user` 模型、迁移、JWT、认证中间件、个人资料 API、健康接口和部署脚本。
- 前端：个人中心请求、令牌存储、Nginx 安全头、Jest 配置和关键流程测试。
- 数据与迁移：新增 `sys_user.token_version`，默认值为 `0`。
- 部署与配置：新增 `JWT_EXPIRATION_SECONDS`，生产前端镜像包含安全头片段。

## 验证策略

- 后端使用 `user.tests` 覆盖个人资料权限、密码变更、令牌版本和健康接口。
- 前端使用 Jest 覆盖当前用户资料交互、令牌存储、用户状态和菜单路由转换。
- 使用 `test_rocky_deployment.py` 防止管理员参数静默重置和健康检查退回弱条件。
- 使用仓库虚拟环境执行 `full` 和 `release`，记录覆盖率与生产构建结果。

## 回滚方案

- 应用回滚时保留 `token_version` 列即可，旧代码会忽略该列。
- 新个人资料接口可独立下线，管理员 CRUD 接口保持兼容。
- 若 CSP 阻断合法资源，可先回滚 Nginx 配置；JWT 版本校验不依赖前端存储方式。
- 部署脚本失败不会写入管理员凭证或修改数据库。
